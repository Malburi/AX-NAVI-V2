AX-NAVI 활용 가이드

레거시 코드베이스에서 찾고, 따라가고, 영향을 보고, 안전하게 고치는 방법을 정리했습니다.

시작하기 워크플로우 아키텍처 상황별 선택 스킬별 사용법 잘 쓰는 요령 자주 묻는 질문

시작하기

1. 프로젝트 폴더에서 Claude Code 열기분석할 프로젝트의 최상위 폴더에서 claude 를 실행합니다.
2. "하네스 초기화 해줘"프로젝트마다 처음 한 번만 합니다. 코드 지도와 프로젝트 맞춤 규칙이 만들어집니다.
3. 말로 부탁하기"결제 승인 어디 있어?", "이거 고치면 어디 영향 있어?" 처럼 평소 말투로 물어봅니다.
명령을 외우지 않아도 됩니다. 말로 부탁하면 알맞은 스킬이 실행됩니다. 자주 쓰는 일은 /ax-navi:find 같은 짧은 별칭으로도 부를 수 있습니다.

전체 워크플로우

  1. 하네스 초기화(처음 한 번): 코드 전체를 AI 없이 파싱해 지도(인덱스)를 만들고, 규모와 예상 비용을 보여 준 뒤 분석 깊이를 고르게 합니다. 이어서 프로젝트 맞춤 CLAUDE.md·에이전트·컨벤션 패턴을 만들고 점수로 검증합니다.
  2. 일상 작업(반복): 찾기 → 흐름 추적 → 영향도 → 변경 → SQL 검토 중 필요한 단계만 골라 씁니다. 모든 답은 코드 지도를 근거로 나옵니다.
  3. 코드를 고친 뒤: "인덱스만 갱신해줘" 로 지도를 최신으로 맞춥니다. AI 를 쓰지 않아 비용이 거의 들지 않습니다.

그림 원본: deploy\diagrams\workflow.drawio (draw.io 에서 열어 고칠 수 있습니다)

아키텍처

구성역할비유
스킬작업 순서를 정한 워크플로우입니다. "영향도 분석" 이면 무엇을 어떤 순서로 확인할지 정해져 있습니다.업무 절차서
에이전트스킬이 부르는 분야별 전문가입니다. 영향 분석, 흐름 추적, SQL 리뷰, 변경 안전성 등을 맡습니다.담당 전문가
결정론 엔진AI 없이 코드를 전수 파싱해 심볼·호출 관계·SQL 사용처·트랜잭션·DB 스키마를 지도로 만들고 질의에 답합니다.정확한 지도
DB 도구Oracle 에 읽기 전용으로 붙어 패키지·프로시저 소스, 의존 관계, 배치 잡, 코멘트를 읽습니다. 설정했을 때만 켜집니다.DB 열람 창구

AI 가 파일을 더듬어 찾는 대신 지도를 먼저 보고 답하므로, 찾은 것·확인했는데 없는 것·확인하지 못한 것을 나눠 알려 줍니다.

스킬별 사용법

처음 한 번하네스 초기화 harness-init

언제
프로젝트를 처음 맡았을 때, 또는 구조가 크게 바뀌었을 때.
방법
프로젝트 최상위 폴더에서 Claude Code 를 열고 말로 부탁합니다. 견적을 보고 Full(심층) 또는 Standard(일상 유지보수)를 고릅니다.
예시
하네스 초기화 해줘
빠르게 하네스 구축해줘        ← Standard 로 바로
레거시 심층 분석으로 하네스 만들어줘   ← Full 로 바로
효과
이후 모든 작업이 이 프로젝트의 구조와 컨벤션을 알고 시작합니다. 만들어진 CLAUDE.md·.claude/ 를 커밋하면 팀원은 다시 초기화하지 않아도 됩니다. Standard 는 Full 의 약 60% 비용입니다. 견적 단계에서 멈춰도 인덱스는 남아 찾기·영향도는 바로 됩니다.

코드 고친 뒤인덱스만 갱신

언제
코드를 고쳤거나 다른 사람의 변경을 받은 뒤.
방법
전체 재초기화 대신 지도만 다시 만듭니다. 기존 AI 보강 내용은 다시 적용됩니다.
예시
인덱스만 갱신해줘
효과
AI 를 쓰지 않아 비용이 거의 없고, 다음 질문이 최신 코드를 근거로 답합니다.

찾기기능 위치 찾기 /ax-navi:find

언제
기능 이름이나 업무 용어만 알고 코드 위치를 모를 때.
방법
기능명·키워드·도메인 용어를 넣으면 관련 파일·클래스·메서드·SQL 을 목록으로 돌려줍니다.
예시
/ax-navi:find 결제 승인
쿠폰 관련 코드 어디 있어?
효과
전체 검색으로 헤매는 시간을 줄이고, 화면·서비스·SQL 까지 한 번에 묶어 봅니다.

이해처리 흐름 추적 /ax-navi:flow

언제
화면 버튼이나 API 하나가 실제로 무엇을 실행하는지 알아야 할 때.
방법
진입점(화면·URL·메서드)을 말하면 컨트롤러 → 서비스 → DAO → SQL → 테이블·외부 시스템까지 따라갑니다.
예시
/ax-navi:flow 수강신청 저장 버튼 누르면 뭐가 실행돼?
이 API 어떻게 처리돼? /api/order/cancel
효과
여러 파일을 오가며 직접 따라가던 일을 한 번에 정리해 받고, 각 단계에 파일:줄 근거가 붙어 바로 확인할 수 있습니다.

판단영향도 분석 /ax-navi:impact

언제
함수·SQL·컬럼·API 를 바꾸기 전에 어디가 영향을 받는지 알고 싶을 때.
방법
바꿀 대상을 말하면 직접·간접 호출처, 같은 테이블을 쓰는 SQL, 화면까지 찾아 위험도와 함께 보여 줍니다.
예시
/ax-navi:impact 이 쿼리 첫 컬럼을 빼면?
TB_APPROVE.APPROVE_DT 컬럼 타입 바꾸면 어디 영향?
이 메서드 호출처 알려줘
효과
"고쳤더니 다른 화면이 깨졌다" 를 미리 막습니다. 테스트해야 할 범위를 근거와 함께 정할 수 있습니다.

변경안전한 수정 /ax-navi:modify

언제
기존 기능을 고쳐야 하는데 회귀가 걱정될 때. 운영 패치·핫픽스 검토에도 씁니다.
방법
사전 영향 분석 → 프로젝트 컨벤션에 맞춘 변경 → 사후 안전성 평가(GO/NO-GO) 순으로 진행합니다.
예시
/ax-navi:modify 승인할 때 승인 시각도 함께 저장해줘
이 패치 적용해도 돼?
효과
컨벤션을 몰라도 기존 코드와 같은 방식으로 고쳐지고, 위험한 변경은 적용 전에 걸러집니다. EUC-KR 같은 기존 인코딩도 지킵니다.

변경신규 기능 생성 /ax-navi:scaffold

언제
기존 패턴 그대로 새 화면·API·기능을 붙여야 할 때.
방법
초기화 때 추출한 컨벤션 패턴을 근거로 Controller·Service·DAO·DTO·SQL·테스트 골격을 만듭니다.
예시
/ax-navi:scaffold 공지사항 첨부파일 기능 추가
주문 취소 기능 만들어줘 컨벤션 따라
효과
비슷한 기존 기능을 찾아 복사·수정하던 일을 줄이고, 리뷰에서 "우리 방식이 아니다" 라는 지적을 줄입니다.

변경빠른 작업 vibe

언제
오타·문구·작은 수정처럼 영향이 뻔한 일을 빨리 끝내고 싶을 때.
방법
영향도·안전성 점검은 건너뛰지만 프로젝트 패턴과 최소 실행 검증은 유지합니다.
예시
바이브로 이 메시지 문구 고쳐줘
그냥 알아서 해줘
효과
작은 일에 무거운 절차를 쓰지 않아 빠르고 비용이 적습니다. 운영 영향이 있는 변경에는 쓰지 마세요.

검토SQL 리뷰 /ax-navi:sql

언제
쿼리 성능·안전성이 걱정되거나 DDL 변경 전에.
방법
SQL 원문, SQL ID, DDL, 변경분 중 아무거나 넣으면 사용처·인덱스 활용·N+1·인젝션·트랜잭션·락·대량 처리·스키마 영향을 함께 봅니다.
예시
/ax-navi:sql 이 쿼리 성능 괜찮아?
ORDER_LIST_S01 인덱스 잘 타?
이 컬럼 추가해도 돼? ALTER TABLE TB_ORDER ADD ...
효과
운영 반영 전 위험한 쿼리를 걸러 내고, 그 SQL 을 쓰는 화면까지 알려 줘 테스트 범위를 정할 수 있습니다.

DBOracle DB 도구 (선택)

언제
업무 로직이 패키지·프로시저·트리거에 있어 소스 저장소만으로는 분석이 끊길 때.
방법
/plugin configure ax-navi@ax-navi 에 읽기 전용 계정을 한 번 넣고 말로 묻습니다. "DB 덤프 받아줘" 뒤 "인덱스만 갱신해줘" 를 하면 DB 객체가 코드 지도에 합쳐집니다.
예시
PKG_APPLY 패키지 소스 보여줘
TB_APPLY 쓰는 프로시저·트리거·배치 뭐 있어?
DB 덤프 받아줘
인덱스만 갱신해줘
효과
Java 에서 PR_APPLY_CHECK 한 줄로 끝나던 추적이 프로시저 안의 테이블·배치 잡까지 이어집니다. 모든 조회는 읽기 전용이며 데이터 조회는 SELECT 한 문장·200행까지입니다.

문서위키 생성 /ax-navi:wiki

언제
인수인계 문서나 시스템 설명서가 필요할 때.
방법
하네스 산출물로 위키 페이지와 인터랙티브 호출 그래프(HTML)를 만듭니다. 원하면 중앙 위키 허브(publish-wiki)에 발행해 여러 시스템을 한곳에서 검색합니다.
예시
/ax-navi:wiki
위키 중앙 DB에 올려줘
효과
코드에서 바로 뽑아 문서와 코드가 어긋나지 않고, 호출 관계를 그림으로 보며 설명할 수 있습니다.

계획마이그레이션 계획 plan-migration

언제
Struts → Spring, iBatis → MyBatis, Java 버전 업그레이드, DB 전환 같은 큰 작업을 앞두고.
방법
인벤토리, 매핑 표, 단계별 계획, 위험 목록, 테스트 전략, 롤백 계획을 만듭니다. Full 깊이로 초기화해 두면 더 정확합니다.
예시
Struts 를 Spring Boot 로 옮기는 마이그레이션 계획 세워줘
Oracle 을 PostgreSQL 로 바꾸면 뭐가 걸려?
효과
전수 인벤토리를 근거로 범위와 위험을 숫자로 잡아 일정·견적 근거로 쓸 수 있습니다.

여러 저장소백엔드·프론트 연동 pair-init · cross-repo-*

언제
백엔드와 프론트엔드(웹·모바일·관리자)가 저장소로 나뉘어 있을 때.
방법
각 저장소를 초기화한 뒤 연결합니다. 이후 영향도가 저장소를 넘어 화면까지 따라가고, 양쪽을 함께 고치거나 만듭니다.
예시
백엔드랑 프론트 연결해줘
이 API 에 필드 추가하는데 프론트도 같이 고쳐줘     ← cross-repo-modify
API 부터 화면까지 공지사항 기능 만들어줘          ← cross-repo-scaffold
효과
"이 컬럼을 빼면 어느 화면이 깨지는지" 를 한 번에 보고, API 계약이 어긋난 곳(드리프트)을 리포트로 받습니다.

그 밖자주 쓰는 보조 기능

기능이렇게 말하세요효과
spec-gate작업 범위부터 정리해줘애매한 요구사항을 질문으로 좁혀 엉뚱한 작업을 막습니다.
legacy-decoder이 PL/SQL 이 무슨 일을 하는지 해석해줘주석 없는 오래된 코드를 업무 언어로 풀어 줍니다.
test-generator이 서비스 테스트 만들어줘프로젝트 테스트 방식에 맞춰 테스트 코드를 만듭니다.
doc-syncer바뀐 코드에 맞춰 문서 갱신해줘코드와 문서가 어긋난 곳을 맞춥니다.
harness-clean하네스 삭제해줘프로젝트에 만든 하네스 파일을 모두 지웁니다.

잘 쓰는 요령

  • 구체적으로 말할수록 정확합니다. "주문 고쳐줘" 보다 "주문 취소 시 재고 복구가 안 되는 문제 고쳐줘" 가 낫습니다. 화면명·URL·SQL ID·테이블명을 알면 함께 적으세요.
  • 고치기 전에 먼저 봅니다. 처음 보는 코드는 /ax-navi:flow → /ax-navi:impact → /ax-navi:modify 순서가 가장 안전합니다.
  • 무게에 맞춰 고릅니다. 운영 영향이 있으면 /ax-navi:modify, 뻔한 작은 수정은 vibe 를 씁니다.
  • 고친 뒤에는 "인덱스만 갱신해줘". 전체 재초기화는 구조가 크게 바뀌었을 때만 합니다.
  • 필요한 단계만 다시 돌립니다. "스킬만 다시 생성", "패턴만 다시", "validator만 실행" 처럼 부분 실행이 됩니다.
  • 답의 근거를 확인합니다. 결과에 붙은 파일:줄 을 열어 보고, "확인하지 못한 것" 으로 표시된 부분은 직접 검토하세요.
  • 팀이 함께 씁니다. 초기화 결과(CLAUDE.md·.claude/)를 커밋해 두면 팀원은 인덱스만 만들어 바로 씁니다.

자주 묻는 질문

하네스 초기화를 매번 해야 하나요?
아닙니다. 프로젝트마다 처음 한 번이면 됩니다. 이후에는 "인덱스만 갱신해줘" 로 충분합니다.
하네스 초기화에 Python 이 필요한가요?
네, Python 3.10 이상이 필요합니다. 인덱싱은 Node 로 하지만 CLAUDE.md·스킬 조립, 검증, 위키 생성은 Python 으로 합니다. 없으면 그 단계가 WARN 으로 빠져 하네스가 완성되지 않습니다. 설치 방법은 설치 가이드의 문제 해결을 보세요.
비용이 걱정됩니다.
인덱싱과 인덱스 갱신은 AI 를 쓰지 않습니다. 초기화는 견적을 먼저 보여 주고, "빠르게" 라고 하면 Standard(Full 의 약 60%)로 실행합니다.
AI 가 틀린 답을 하면요?
모든 답은 코드 지도를 근거로 하고 파일:줄 을 붙입니다. 지도에 없는 내용은 추측하지 않고 "확인하지 못함" 으로 알려 줍니다.
DB 비밀번호가 안전한가요?
읽기 전용 계정을 쓰세요. Windows 에서는 비밀번호가 %USERPROFILE%\.claude\.credentials.json 에 평문으로 저장됩니다.
지원하는 기술은요?
Java(Spring·Struts·MyBatis)·JavaScript/TypeScript·Python·Go·C# 을 비롯해 Nexacro·PowerBuilder·Pro*C·PL/SQL 같은 레거시까지 다룹니다. 자세한 목록은 README 의 지원 스택을 보세요.
