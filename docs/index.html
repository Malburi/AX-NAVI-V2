v2 · 인덱스 2.0

코드에 안 보이는 연결까지,
고치기 전에 찾아냅니다.

레거시 화면은 서버를 TransData.do?worker=…&action=… 처럼 문자열로 부르고, 결과를 rtInfo[1][2] 처럼 위치로 읽는 일이 흔합니다. 호출이 코드에 없으니 grep 으로도, 백엔드만 봐서도 보이지 않습니다. 인덱스는 이 연결을 설정 없이 찾아 백엔드 메서드 · SQL 컬럼 순서와 잇고, impact 한 번으로 다른 저장소 화면까지 "이 컬럼을 빼면 어디가 깨지는지"를 돌려줍니다.

  • 문자열 디스패치를 스스로 알아냅니다

    화면의 호출 모양에서 "이 파라미터가 빈 이름, 저 파라미터가 메서드"라는 규칙을 추론하고, 빈과 메서드가 실제로 있을 때만 잇습니다. 그래서 이런 메서드를 죽은 코드로 잘못 보지 않습니다.

  • "안 쓰는 것 같으니 빼줘"에 멈춥니다

    요청의 전제가 인덱스 사실과 다르면 쓰는 곳 목록과 함께 선택지를 내고 멈춥니다. 고친 뒤에도 위치로 읽는 화면이 남아 있으면 훅이 Claude 가 이어서 처리하게 합니다.

  • 절차는 가볍게

    인덱스 신선도는 훅이 확인하고, 영향도는 인덱스로 먼저 계산해 넣습니다. 고친 뒤 LLM 재평가는 DDL · 트랜잭션 · 인증 · 데이터 변경 같은 위험한 변경에서만 한 번 돕니다.

DB 덤프 · 0.3

업무 로직이 오라클 패키지에 있어도,
지도가 끊기지 않습니다.

수강신청 가능 여부 · 자동 수료 판정 같은 핵심 규칙이 PR_APPLY_CHECK 한 줄 호출 뒤에 숨어 있으면 소스 저장소만으로는 분석이 거기서 끊깁니다. DDL 과 프로시저 소스를 덤프로 프로젝트 안에 두고 db_dump_paths 로 알려 주면, 같은 인덱스에 이어 붙습니다.

  • Java 호출부터 프로시저 · 테이블까지

    {call PKG.PROC} · EXEC · CALL 호출이 프로시저 정의로 이어지고, 그 프로시저가 읽고 쓰는 테이블 · 부르는 다른 프로시저가 한 질의로 나옵니다. 테이블을 바꾸면 영향받는 프로시저 · 트리거도 보입니다.

  • Oracle · MSSQL · MySQL · PostgreSQL

    방언은 파일 내용으로 자동 판별합니다. GO 경계 · DELIMITER · $$ 본문 · /*!50003 */ 조건부 주석처럼 방언마다 다른 모양을 따로 처리합니다.

  • 없는 덤프도 알려 줍니다

    소스에는 호출이 있는데 덤프에 정의가 없는 프로시저를 호출처 수 순으로 모읍니다. 어떤 덤프를 더 받아야 하는지 그대로 보입니다. 데이터 행은 넣지 마세요 — 스키마와 소스면 충분합니다.

분석 깊이 게이트

얕은 분석은 점수를 받기 전에
먼저 막습니다.

LLM 이 인덱스 요약만 옮기고 업무 규칙 · 업무별 흐름 절을 "미수행"으로 비워도 평가가 통과하던 문제가 있었습니다(실측: 소스 2,737파일, 리포트 6KB, 84점). 평가 전에 결정론적으로(LLM 없이) 깊이를 재서, 얕으면 영역별 심층 분석을 처방합니다.

  • 막는 신호는 규모와 무관한 둘뿐

    비어 있는 필수 절이 2개 이상이거나 파일:줄 근거가 하한의 25% 미만이면 FAIL 입니다. 서술 분량 · "미수행" 표현은 프로젝트 둘로 정한 경험값이라 WARN 만 냅니다.

  • 작은 프로젝트도 똑같이, 처방은 작게

    영역 수는 파일 400개당 1개(1~7), 영역당 약 25만 토큰입니다. 견적이 30만 토큰 이하(영역 1개)면 묻지 않고 진행하고, 그 이상이면 확인을 받습니다. 작은 프로젝트라고 분석을 덜 하지는 않습니다.

  • 거절해도 숨기지 않습니다

    사용자가 심층 분석을 거절하면 declined 로 기록하고 평가는 -5점만 매깁니다. 같은 일을 다시 시키지 않지만, 보고에는 "분석 깊이 미달"이 그대로 남습니다. 임계값은 depth_gate 설정으로 조정하거나 끕니다.

정직한 보고

"없다"는 것도
답의 절반입니다.

  • 찾은 것 · 확인했는데 없는 것 · 확인하지 못한 것

    셋을 나눠 보고합니다. "관련 컬럼 없음 · SQL 0건" 같은 사실이 판단에 바로 쓰입니다.

  • 백엔드와 프론트엔드를 함께

    pair-init 으로 짝 저장소를 연결해 두면 다른 저장소에 미치는 영향을 인덱스가 한 번에 따라갑니다. 백엔드 1개 + 클라이언트 여러 개(웹 · 모바일 · 관리자)도 됩니다.

  • 인덱스가 못 푼 것은 못 풀었다고 말합니다

    문자열 디스패치 · XML 배선처럼 정적으로 확정하지 못한 호출은 미해결로 세어 두고, 호출처가 없다고 단정하지 않습니다.

안전장치

고치는 동안에도,
훅이 곁에서 지켜봅니다.

플러그인이 켜져 있으면 Claude Code 의 훅이 인덱스 신선도 · 사전 영향도 · 인코딩 보존 · 고친 뒤 확인을 맡습니다. 지침에만 적어 둔 규칙이 아니라 실제로 실행되는 코드입니다.

  1. 세션 시작

    인덱스 신선도 확인

    인덱스가 있으면 소스 지문을 비교하고, 바뀐 저장소만 다시 만듭니다.

    AI 0원
  2. 질문 입력

    사전 영향도

    영향도 · 수정 요청이면 인덱스로 계산한 영향 범위를 맥락으로 먼저 넣습니다.

    AI 0원
  3. 셸 명령 전

    무리한 명령 차단

    디스크 전체 검색(find /)을 막고, 평가 서브에이전트는 요청당 1번으로 제한합니다. 셸로 소스를 쓰는 명령의 승인은 AXNAVI_SHELL_WRITE_GUARD=1 로 켭니다(기본 꺼짐).

    AI 0원
  4. 읽기 · 쓰기

    레거시 인코딩 보존

    EUC-KR 같은 파일을 읽고 쓸 때 인코딩을 지킵니다.

    AI 0원
  5. 답이 끝날 때

    고친 뒤 확인

    UTF-8 로 바뀐 EUC-KR 파일을 되돌려 쓰고, SELECT 순서를 바꿨는데 위치로 읽는 화면이 남았으면 Claude 가 이어서 처리하게 합니다.

    AI 0원

Edit · Write 승인은 Claude Code 의 권한 모드를 그대로 따릅니다. 훅 설정은 hooks/hooks.json, 판정 코드는 packages/plugin/src/hooks.mjs 에 있습니다.

지원 스택

SI/SM 현장에 실제로 남아 있는 스택.

FULL 은 심볼 · 호출 · SQL · 트랜잭션까지 결정적으로 뽑는 스택이고, PARTIAL 은 에이전트가 원문을 직접 읽어 확인한 뒤 수정하는 스택입니다. 읽을 수 없는 형식만 수정을 보류합니다.

Java · Spring · Struts · MyBatis심볼 · 호출 그래프 · SQL · 트랜잭션 · 스키마FULL
JavaScript · TypeScript · Vue · React일부 동적 패턴은 PARTIALFULL
Python · Go · C# / .NETFULL
SQL / DDL (Oracle · MSSQL · MySQL · PostgreSQL)테이블 · 인덱스 · 뷰 · 시퀀스 · 시노님FULL
ASP.NET Core · Nexacro (XJS)전용 어댑터로 보강FULL
JSP · Struts XML · XFDL · WinForms Designer · DevExpressPARTIAL
PL/SQL · T-SQL · MySQL · PL/pgSQL 루틴패키지 · 프로시저 · 함수 · 트리거, 호출 · 정적 SQL · Java {call} 연결PARTIAL

스택별 탐지 시그니처와 마이그레이션 시나리오는 지원 스택 매트릭스에 있습니다.

설치

Claude Code 와 Node.js 면 충분합니다.

Node.js 18 이상이 필요하고 npm 의존성은 0 입니다. Python 3 은 하네스 조립 · 위키 생성 보조에만 씁니다. Claude Code 는 claude plugin 을 지원하는 최신 버전이어야 합니다.

설치 (터미널)
claude plugin marketplace add Malburi/AX-NAVI-V2
claude plugin install ax-navi@ax-navi --scope user
시작 (프로젝트 루트에서)
cd 내-프로젝트
claude
# Claude Code 안에서:  하네스 초기화 해줘

설치 뒤 새 세션을 시작하거나 /reload-plugins 를 실행하세요. Claude Code 대화창에서는 /plugin marketplace add Malburi/AX-NAVI-V2 → /plugin install ax-navi@ax-navi 로도 됩니다.

이전 주소(Malburi/AX-NAVI)로 등록해 둔 경우에는 마켓플레이스를 다시 등록합니다.

다시 등록
claude plugin uninstall ax-navi@ax-navi --scope user
claude plugin marketplace remove ax-navi
claude plugin marketplace add Malburi/AX-NAVI-V2
claude plugin install ax-navi@ax-navi --scope user
갱신
claude plugin marketplace update ax-navi
claude plugin update ax-navi@ax-navi

적용은 새 세션에서 됩니다. 판마다의 변경은 변경 이력에 있습니다.
